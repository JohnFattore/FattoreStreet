# Entertainment

## Why

Part of the author's public workspace in the vision is keeping personal recommendations. This branch
holds the non-food kind: books, films, shows, music, podcasts, games and websites the author thinks
are worth someone's time. Without it, those recommendations are scattered and can't be shared.
(inferred: secondary to the finance core)

The list is kept in the main API (Django) and edited through its admin screens, because the author
is the only writer and a built-in admin needs no code to maintain. (inferred)

This branch has one part:

- [Recommendations](recommendations.md): the author's curated list, readable by anyone.

## Non-goals

- **Ratings or reviews from visitors.** It's the author's list. (inferred)
- **Pulling in outside catalogue data** such as cover art or scores, which would bring licensing
  questions for little gain. (inferred)

## Open questions

  stored list, while the web app has a separate entertainment page with a hard-coded album list
  that isn't linked from the navigation. Which one is the real page, and should the other go?
