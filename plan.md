5. The split filing scan runs unconditionally (EquitySplitDetector.java:95), before ratio-change detection, for every equity ticker on every weekly re-detection. Most tickers have never split. Fetching split-date candidates lazily, only when an XBRL ratio jump or an unexplained price break exists, would eliminate the single largest HTTP block for the typical ticker.
6. Filings are immutable, but extractions aren't persisted. The ticker-scoped cache lives only for one run, so every weekly re-scan re-downloads and re-regexes the same 250–400 documents. Persisting extraction results keyed by accession number (candidates, ex-dates, tuples) and scanning only new accessions would cut steady-state runtime and SEC load by roughly an order of magnitude. This is the one change with real payoff.

Simplifiable only with evidence: the filing date service runs two parallel extraction systems (anchored regex PatternSpecs and the sentence-intent classifier with proximity boosts) and merges their outputs. One probably subsumes the other by now, but this was tuned through the accuracy passes, so I'd only prune it with the yfinance validation harness (validateWithYfinance) as the referee, comparing candidate coverage before and after.
